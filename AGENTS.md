## Skill Loading

Before editing files for a substantial task:
- Run `pnpm dlx @tanstack/intent@latest list` from the workspace root to see available local skills.
- If a listed skill matches the task, run `pnpm dlx @tanstack/intent@latest load <package>#<skill>` before changing files.
- Use the loaded `SKILL.md` guidance while making the change.
- Monorepos: when working across packages, run the skill check from the workspace root and prefer the local skill for the package being changed.
- Multiple matches: prefer the most specific local skill for the package or concern you are changing; load additional skills only when the task spans multiple packages or concerns.

## Project Context

### Scaffolding

This app was generated with the TanStack CLI, blank React starter, no add-ons:

```bash
npx @tanstack/cli@latest create my-tanstack-app --agent --package-manager pnpm --tailwind
```

Notes on that command as actually run (CLI v0.69.5):
- `--tailwind` is deprecated/ignored — Tailwind is bundled by default in every TanStack Start scaffold now, so it's present regardless of the flag.
- `chosenAddOns` in `.cta.json` is `[]` — no partner integrations (auth, db, deployment target, etc.) were selected. There was nothing to merge from a separate host-platform template; this app was scaffolded directly in place.
- Default toolchain kept: Vite ^8, TypeScript, Vitest, TanStack Router (file-based routing, auto code-splitting via `@tanstack/router-plugin`), TanStack React Devtools, Tailwind CSS v4 (`@tailwindcss/vite`), `lucide-react` icons.

Follow-up TanStack Intent commands run after scaffolding:

```bash
npx @tanstack/intent@latest install   # wired skill-loading guidance into AGENTS.md
npx @tanstack/intent@latest list      # 9 intent-enabled packages, 31 skills available locally
```

Re-run `pnpm dlx @tanstack/intent@latest list` any time to see the current set — do not hardcode skill names from memory since versions/skills evolve; the `install` step deliberately replaced the once-off hardcoded skill dump in this file with a live pointer (see the `intent-skills` block above).

### Stack

- Framework: TanStack Start (React 19), file-based routing under `src/routes/`.
- Root route/shell: `src/routes/__root.tsx`. Home/about demo routes: `src/routes/index.tsx`, `src/routes/about.tsx`.
- Styling: Tailwind CSS v4 via `@tailwindcss/vite`, global styles in `src/styles.css`.
- Devtools: `@tanstack/react-devtools` + `@tanstack/router-devtools` + `@tanstack/devtools-vite` (dev-only; stripped from production build automatically — confirmed via `pnpm build` output "Removed devtools code from: /src/routes/__root.tsx").
- Testing: Vitest + Testing Library, `pnpm test`.
- No backend/database/auth/deployment integrations were added — this is intentionally a blank starter.

### Environment variables

None required. The generated app makes no calls to `process.env` or `import.meta.env` anywhere in `src/` or `vite.config.ts`. If you add server functions, API routes, or third-party integrations later, prefix client-exposed vars with `VITE_` (see the `start-core/execution-model` Intent skill for the isomorphic env-var safety rules before wiring anything up).

### Deployment

Not yet configured for any target. Before deploying, load `@tanstack/start-client-core#start-core/deployment` via Intent — it covers Cloudflare Workers, Netlify, Vercel, Node/Docker, Bun, and Railway, plus selective SSR / SPA / prerendering options.

### Known gotchas

- `pnpm` field `pnpm.onlyBuiltDependencies` in `package.json` triggers a pnpm warning ("no longer read") on install/build — cosmetic, left as generated by the CLI.
- `--tailwind` flag on `tanstack/cli create` is a no-op; don't rely on it to toggle Tailwind on/off. To remove Tailwind, follow the manual steps in `README.md` ("Removing Tailwind CSS").
